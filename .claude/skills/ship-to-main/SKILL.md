# Ship to main (항상 새 PR → main 자동 머지)

이 저장소의 표준 전달 워크플로. **모든 작업 완료 시** 아래 절차를 따른다.
사용자가 이 세션에서 "항상 새 PR로 main에 자동 머지"를 표준으로 고정 요청함.

## 확정된 정책

- **머지 대상 브랜치**: `main`
  - `main`이 없으면(신규 저장소 등) 현재 기본 브랜치 tip에서 생성한다:
    `git push origin origin/<default-branch>:refs/heads/main`
  - PR 생성 시 **항상 `base=main`을 명시**한다 (저장소 기본 브랜치가 main이 아닐 수 있음).
- **머지 방식**: 즉시 머지(`squash`). 브랜치 보호/필수 체크가 없는 현재 상태에 적합.
  - 필수 체크가 설정돼 있어 즉시 머지가 거부되면 GitHub auto-merge(`enable_pr_auto_merge`)로 폴백.
- **작업 브랜치**: 절대 `main`에 직접 커밋하지 않는다. 매 작업마다 새 작업 브랜치를 만든다.

## 절차

1. **사전 점검**: `npm run lint`와 `npm run build`가 통과하는지 확인한다.
   실패하면 머지하지 말고 먼저 고친다.

2. **새 작업 브랜치 생성**: 변경 성격을 담은 이름으로 새 브랜치를 만든다.
   예: `git checkout -b claude/<주제>-<짧은해시>`
   (세션에 지정 브랜치가 있으면 그 브랜치를 그대로 작업 브랜치로 사용해도 된다.)

3. **커밋 & 푸시**: 명확한 한국어 커밋 메시지로 커밋 후
   `git push -u origin <branch>` (네트워크 오류 시 2s→4s→8s→16s 백오프로 최대 4회 재시도).

4. **PR 생성**: `create_pull_request`로 `base: main`, `head: <작업 브랜치>` 지정.
   제목/본문은 변경 내용을 요약. (저장소에 PR 템플릿이 있으면 그 구조를 따른다.)

5. **자동 머지**:
   - 1차: `merge_pull_request`로 `merge_method: "squash"` 즉시 머지.
   - 즉시 머지가 거부되면(필수 체크 대기 등): `enable_pr_auto_merge`로 auto-merge 활성화.

6. **정리 & 보고**: 머지된 PR 번호/URL과 머지 방식을 사용자에게 보고한다.
   필요 시 원격 작업 브랜치는 삭제 가능(정책상 유지해도 무방).

## 주의

- `main`에 직접 push 금지. 항상 PR 경유.
- 즉시 머지는 되돌리기 어려우므로, lint/build 실패 상태에서는 머지하지 않는다.
- 민감정보(토큰/키/`.env`)가 diff에 포함되지 않았는지 확인 후 머지한다.
